## 2026-07-11 — AIR192 crackle root-caused by MEASURING the signal, not guessing candidate N+1
Goal (G): eliminate the light continuous crackle on the AIR192 440Hz round-trip so the recovered sine is clean at native rate, like UCA222/US-2x2.
What drifted / what went wrong: three consecutive code fixes (s_outBias smoothing, m_fbRate exponential smoothing, IN 32->s16 rounding) each shipped on a plausible hypothesis and each measured ZERO or wrong effect on the crackle. Classic stuck-loop: guessing a new candidate cause each round instead of characterizing the actual defect. The prior PRD note even declared the remaining work "beyond this codebase" (xHCI microframe tracing / device firmware) -- a premature out-of-scope escape.
Fix / resolution: applied BBCR properly -- STOPPED guessing, ran a precise cross-validated WAV analysis (quadrature demod + independent zero-crossing) on the actual capture. This revealed the defect was FM (pitch jitter), NOT the AM/clicks/quantization every prior hypothesis assumed: a 26.382Hz (1819-sample) harmonic comb = linear-interpolation error in the IN-side fractional resampler (input_usb.cpp), modulated by the continuously-wrapping fractional read phase under the AIR192's ~0.055% clock offset. Fix = replace 2-point linear interp with 4-point cubic Hermite (~40dB lower reconstruction error).
Generalizes to: when N consecutive fixes measure zero effect, the bug is NOT another untried code candidate -- it's that the DEFECT ITSELF is mischaracterized. Measure the real output's precise structure (AM vs FM, exact modulation frequency, spectral comb, quantization grid) BEFORE proposing any fix. A cross-validated measurement (two independent methods agreeing) outweighs a hundred plausible code hypotheses. Also: "beyond this codebase" is almost never true when a reachable measurement hasn't been exhausted first.

## 2026-07-16 — Varispeed phase-lock is a structural impossibility, not a tunable bug
Goal (G): loops resample to chase Link tempo (read at effectiveRate for pitch) AND stay locked to the recorded phrasing, never drifting or flipping to the offbeat.
What drifted / what went wrong: four sim-backed control-law iterations (pin-block-to-masterPhase; free-run+bounded-nudge; separation of blockIndex vs subFrac; rate-trim vs unwrapped phase error) all failed to hold tight phrasing. Root cause is not a bug: a loop of native length L blocks, resampled to effectiveRate, occupies L/effectiveRate blocks of WALL-CLOCK per repeat. To phase-lock to an M-block phrase you need L/effectiveRate == M (or a divisor). But effectiveRate is set by Link-tempo-vs-loop-native-tempo, so unless the loop was recorded AT the current Link tempo, its resampled period does not divide the phrase — two different periods, no control law reconciles them. Pinning the block index to masterPhase forces the read rate to the master rate (kills pitch, sim showed 61 samp/block at rate=0.5 instead of 32); free-running at effectiveRate drifts off the phrase. Wrapped phase error also has multiple equilibria -> offbeat flips.
Fix / resolution: SURFACED to the user (BBCR bounded-retry exhausted, structural not tunable). The only ways to have BOTH exact pitch and exact phrasing: (a) NATIVE-RATE — first loop defines the tempo, Link adopts it, loops play at rate=1, integer phase lock, no resampling, cannot drift (the user's original instinct 'stop Link, restart in new tempo'); or (b) accept that resampled loops re-align only at phrase boundaries (hard-snap each wrap) with a small in-phrase wander — good phrasing, slight looseness mid-phrase. Reverted my divergent varispeed edits to last-known-good before choosing.
Generalizes to: when a control law will not converge across several honest attempts, check whether the two requirements are simultaneously satisfiable at all (dimensional/periodicity analysis) BEFORE tuning gains — a structural impossibility surfaces as 'converges but not tight enough' at every gain, which is the tell. Resampling + hard phase-lock to a foreign grid is such a case.
