## HARDWARE VALIDATION RESULT: WLAN-enabled kernel HANGS at boot on real Pi4 (before network/syslog) — commit ef5deaa, tested 2026-06-17

Netbooted dist/kernel7l-wlan.img (LOOPER_ENABLE_WLAN=1, 1073108B) on a real Pi4 over TFTP. The bootloader fetched the kernel fine (kernel7l.img -> .103 1073108B confirmed in dev-server log) and handed off, but the kernel HUNG before bringing up the network: no static 192.168.137.100, no ICMP, ZERO syslog in 150s+, .100 never appeared in ARP. The safe WLAN-disabled kernel boots normally. Since m_WLAN.Initialize()/JoinOpenNet("ticker") run in CKernel::Initialize() BEFORE Run() starts the network+syslog (first syslog line is "Looper starting" at top of Run()), a hang there is invisible to UDP/syslog and matches the symptom exactly => the WLAN radio bring-up (plan9/bcm4343 SDIO init or the unbounded JoinOpenNet scan/assoc) wedges the boot on real hardware. This is the failure the AGENTS HARDWARE-VALIDATION-PENDING caveat warned about; host tests (linkWire/ghost/session/rxdemux) cannot exercise real radio init.

DIAGNOSTIC SURFACE: pre-network, the ONLY logs are HDMI screen + serial (miniuart) via CLogger — syslog/:4445 are unavailable until Run() brings up Ethernet. To locate the exact hang line, read the HDMI screen (or a UART console) for the last line before freeze (expect USB-audio Configure() then the WLAN init attempt; possibly a panic/assert).

FIX DIRECTION (next): bound/guard the WLAN bring-up so a hang becomes timeout+continue (boot proceeds, WLAN degraded) rather than wedging Initialize(); or move WLAN init AFTER network is up so failures are observable via syslog; or fix the specific SDIO/JoinOpenNet hang. Do NOT default LOOPER_ENABLE_WLAN on until a Pi boot reaches :4445 with wlan=joined/hosting-ticker. Netboot makes iteration safe (power-cycle reverts; swap tftproot kernel). dev-server.js auto-update (tftp-server.js, every 30s) OVERWRITES tftproot kernels with the latest GitHub RELEASE (which is WLAN-disabled + possibly stale Apr-6) and reboots the Pi — run with LOOPER_NO_AUTO_UPDATE=1 when testing a local kernel.
