## USB enumeration tolerates an unsupported/UAC2 interface instead of halting boot (commit 8027864)

Plugging a UAC2 device (Tascam US-2x2) used to HALT the kernel at boot with assert(m_pInterfaceDesc != 0) in Circle lib/usb/usbfunction.cpp. Mechanism: our CUSBAudioDevice::Configure runs SelectInterfaceByClass(1,2,0,..) for the UAC1 class triple; a UAC2 streaming interface uses protocol 0x20 so nothing matches, and the failed search advances the config parser past the last interface -> current descriptor null -> the next CUSBFunction ctor asserted and halt()ed BEFORE network/sockets (silent boot hang, only :4445-down + ICMP-maybe). FIX (forked patches): patches/usbfunction.cpp makes both ctors + every accessor tolerate a null interface descriptor (Configure->FALSE, GetNumEndpoints->0, GetInterface{Class,SubClass,Protocol,Number}->0xFF, SelectInterfaceByClass->FALSE, GetInterfaceDescriptor->possibly-null); patches/usbconfigparser.cpp GetCurrentDescriptor() returns 0 gracefully when !m_bValid (no assert); patches/usbdevice.cpp config loop skips a function whose interface descriptor is null (delete+continue). usbfunction.cpp added to build-local.ps1 + .github/workflows/build.yml usb patch lists (usb_Makefile OBJS already builds usbfunction.o). LIVE-verified: Pi boots with US-2x2 plugged, :4445 reachable at ~46s, joined-ticker synced. The device still won't be used (Circle host audio is UAC1) - it's just a harmless skipped no-op. Whenever a plugged USB device wedges boot before network, suspect a CUSBFunction/config-parser assert on an unexpected descriptor.
