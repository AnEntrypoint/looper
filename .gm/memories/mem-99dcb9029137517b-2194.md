## UCA222 extra latency (past-week) = UAC2 OUT compat applied to ALL devices; now UAC2-gated + UCA222 reader rate-trim (commits 87710dc + b4d4f6c, 2026-06-23)

SYMPTOM: looper monitoring/round-trip latency grew after the Tascam US-2x2 (UAC2) compatibility work. TWO causes, both now fixed and gated to UCA222 (UAC1):

(1) DOUBLE-BUFFER applied globally (commit 87710dc): usbaudiodevice.cpp Configure submitted BOTH OUT URBs (StartOutRequest(0); StartOutRequest(1)) for EVERY device -> 2 OUT URBs in flight = ~1 URB period extra latency. The Tascam (high-speed async OUT) needs it (misses microframes in the per-URB re-arm gap); the full-speed UCA222 (UAC1, 1ms re-arm) never did and ran single-buffered before. FIX: StartOutRequest(0) always; StartOutRequest(1) only if (m_bUAC2 && m_pEndpointFb). m_bUAC2 set in ConfigureUAC2() before the OUT submission. OutCompletion re-arms per-slot so single slot-0 self-sustains; ~dtor delete of null slot-1 is safe.

(2) UCA222 OUT-lag DRIFT (commit b4d4f6c): UAC2 paces the SEND rate via the feedback PI in StartOutRequest (s_outBias holds ring avail~256), but UAC1/UCA222 has NO send-rate controller, so AudioOutputUSB::outHandler read 1:1 from a 128-samp seed and the lag crept toward the overflow resync edge. FIX (output_usb.cpp outHandler, UAC1 only via g_audioUAC2==0): seed OUT_RD_TARGET=96 (~2ms) + a deadband(+/-32) skip/repeat rate-trim (one sample/call, the OTG-tap click-tolerant scheme) to PIN avail near 96 instead of drifting. UAC2 keeps 128 seed + passive read (skipped by the trim so the two controllers never fight). The avail=256 PI + N=8 multi-iso were ALREADY UAC2-only (inside if(m_bUAC2 && m_pEndpointFb)).

PRINCIPLE (user): compatibility latency added for one device must be CONDITIONAL on that device, not global. Net: UCA222 single-URB + pinned ~2ms OUT lag (low latency restored); Tascam keeps double-buffer + its PI. Verify: :4445 UAUD outDeliv ~1000/s single-URB cadence + outAvail held ~96 + outUR not climbing on UCA222. Build: rm output_usb.o/usbaudiodevice.o + ar d from libaudio.a/libusb.a + remake (the recurring 'make says up-to-date, must ar r re-add' trap).
