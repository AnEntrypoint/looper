## Looper second loop 'records then silent, never starts' = quant rounded UP -> stuck deferred (commit follows 1b3a1d1)

Symptom: consecutive (second) loop recorded (red LED) then never played. Root cause: _calcQuantizeTarget(M>0) picked the nearest of {M/8..8M} to m_record_block BY DISTANCE. A SHORT tap (rec << M/8) snapped UP to M/8 > rec, so updateState(PLAY) hit the ELSE branch (m_quantizeTarget=target, willPlay=true = DEFERRED), leaving the clip in CS_RECORDING_MAIN waiting for record_block>=target which never came once the operator stopped feeding it -> silent, never starts. FIX (user rule: round DOWN for short, UP for near-phrase): nearest-on-log2 grid {floor=CROSSFADE*2,M/8..8M} with safe-DOWN bias — largest candidate <= rec, round up to next only if rec*2 > c (strict past midpoint). Short tap -> division <= rec, target<=record_block so _startEndingRecording fires immediately and the clip PLAYS; near-phrase rounds up to the phrase multiple (intended 505 play-through, small extend); exact/midpoint rounds down (never stalls). RULE: a consecutive stop must ALWAYS yield target<=record_block for sub-phrase taps so it plays immediately; only deliberately-near-a-boundary taps may defer (and only by < the recorded length). Host test scripts/test-second-loop-play.cpp.
