## Resolved mutable: microrepeat-design

loopMachine.cpp:677-691 effects stage processes m_input_buffer in place; 702 cbWriteBlock(m_input_buffer) records the wet signal; clips advance m_play_block on masterPhase UNCONDITIONALLY (loopClipUpdate.cpp, confirmed mem pause-update-gating). DESIGN: insert a microrepeat stage on m_input_buffer AFTER effects (691) and BEFORE cbWriteBlock (702). It is a pure output-stage effect: while a latch is held it captures a beat-fraction slice of the processed m_input_buffer into a small ring and replays that slice looping (over-writing m_input_buffer), and it NEVER touches clip m_play_block/m_masterPhase - so the loops keep advancing underneath and on release the live signal resumes exactly where it would have been (ephemeral/non-destructive to position). Because it sits on m_input_buffer before cbWriteBlock and after the SHIFT loop-fold (m_loopFoldGain) + effects, under SHIFT the stuttered loops+input are what gets recorded (records into a recording loop with stutter). Beat length = m_masterLoopBlocks/16 blocks (16 beats per phrase, gridStep), * AUDIO_BLOCK_SAMPLES samples; divisions 1, 1/2, 1/4, 1/8, 1/16 beat = notes 82,83,84,85,86. Latch state added to LiveParams (paramSnapshot) as microRepeatDiv, set by handleMidi note-on/off 82-86 (published Core 2), read in loopMachine::update (Core 1). Beat-synced: slice boundary aligned to masterPhase so the repeat restarts on the grid. Note 84 currently == APC_BTN_FORMAT; the 82-86 microrepeat handler runs BEFORE the button dispatch so it overrides.
