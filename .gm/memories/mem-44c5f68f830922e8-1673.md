## Looper pause/resume OFFBEAT fixed: phase-lock the first loop L==M (commit c6f129a)

Symptom: resuming a paused clip sometimes restarted it on the offbeat instead of in phrase; pause/resume must NOT change phrase sync. Root cause (confirmed cause C via scripts/test-resume-phase.cpp): loopClipUpdate.cpp playback advance phase-locked ONLY sub-phrase loops (L<M) to play_block=(masterPhase-recordStartPhaseOffset)%L; the first loop (L==M) and phrase-or-longer SELF-ADVANCED play_block++. On resume, _startPlaying (loopClip.cpp:151) re-anchors play_block from the phase formula, which DIVERGES from the self-advancing head whenever recordStartPhaseOffset != 0 (a first loop recorded mid-phrase). Sim: M=L=5520 off=1234 resume@5611 -> ref(never-paused)=3193 vs resumed=4377 = OFFBEAT by 1184 blocks. (off==0, sub-phrase, and L>M all stayed in sync; only L==M with offset!=0 broke.)
FIX: loopClipUpdate.cpp:197 condition m_num_blocks<masterLen -> m_num_blocks<=masterLen, so the first loop uses (masterPhase-offset)%L for BOTH play and resume (one formula). Block i was recorded at phase offset+i so (phase-offset)%L==i is the TRUE block-to-phase mapping (advances 1/block, wraps at L like self-advance, but re-derivable from masterPhase => resume lands on the same grid the phrase is at). Only L>M (and no-master) still self-advances. First-loop exact-region invariant PRESERVED (verified): starts block 0 at recorded downbeat, covers [0,L) in order, seam wrap fires once/cycle; test-first-loop-region.cpp still ALL PASS. RULE: any clip whose length divides-or-equals the phrase (L<=M) MUST be phase-locked, never self-advancing, so pause/resume/restart are phase-identical.
