## Looper USB gamepad control surface (patches/gamepadInput.{h,cpp}, gamepadState.h)

A generic USB HID gamepad (Circle CUSBGamePadStandardDevice, registers as upad1..4) drives the SAME controls as the APC Key 25 by synthesizing APC MIDI bytes through pTheAPC->handleMidi. NO new DSP -- every mapping reuses an existing tested path. MAPPING: Z-axis(GP_AXIS_Z)=transpose -12..+12 (CC52, center deadzone); Z-rotation(Rz)=formant (CC53); X-axis VERTICAL(Y) down=lowpass(CC55 closes)/up=highpass(CC51 opens); X-axis HORIZONTAL(X)=resonance (CC54, bipolar magnitude); LT/RT analog triggers=delay amount(CC49)/time(CC50) w/ digital-button fallback; R1 bumper=reverb MAX(CC48) momentary; L1 bumper=SHIFT (note 0x62); remaining buttons=loopers (gpButtonBitToLooper order table -> gpLooperToPadNote pad note -> _onPadPress full record/finish/pause/erase gesture); HAT/dpad=glitch microRepeat speeds (notes 82-85). CROSS-CORE (load-bearing): status handler fires in USB ISR (Core0), only SNAPSHOTS TGamePadState->GpState into a coalescing latest-state buffer (publish-after-write seq); processTick() on Core2 (gamepadProcessTick in coreControlPlaneTick after usbMidiProcess) diffs vs last-applied + emits. Axes coalesce latest-wins; button/hat edges recovered by diff (Core2 ~1kHz vs ms presses). gamepadProcess(bPnP) binds/unbinds on plug; unplug clears momentary (shift/reverb/glitch). Axis index = HID descriptor declaration order (NOT guaranteed) -> named tunable GP_AXIS_* consts, one-line fix per device. Deadzone GP_DEADZONE_FRAC=0.12. :4445 GPAD verb (connected/axes/buttons/hat/dropped/shift/reverb). scripts/test-gamepad.cpp ALL PASS; build kernel7l.img +28KB, 103 gamepad symbols. HARDWARE-VALIDATION-PENDING (real pad axis ordering by ear). See [[looper-grid-presets-ui]] [[looper-usb-midi-host]] [[looper-microrepeat-full]].
