## Looper NO-OUTPUT real root cause = kernel built WITHOUT LOOPER_USB_AUDIO (wrong audio path) -- USER-CONFIRMED FIXED 2026-06-22

Symptom: input VU on APC but NO output audio. The handler-late-bind theory was a RED HERRING. ACTUAL ROOT CAUSE: the kernel was compiled for the DEFAULT CS42448/TDM audio path, not USB. audio.cpp: with NEITHER LOOPER_USB_AUDIO nor LOOPER_OTG_AUDIO defined, the #else branch sets USE_CS42448=1 -> the AudioStream graph instantiates AudioInputTDM/AudioOutputTDM, NOT AudioInputUSB/AudioOutputUSB. So AudioOutputUSB::update (the OUT-ring writer) was never in the graph; the USB OUT URB (outHandler, late-bound) read an empty ring -> silence. MUST build the app with `make ... LOOPER_USB_AUDIO=1 LOOPER_OTG_AUDIO=1 ARM_ALLOW_MULTI_CORE=1 CHECK_DEPS=0`. The compile pragma 'Looper::audio.cpp using USB AUDIO' confirms the right path; absence (or 'using CS42448 (octo)') = wrong build. The define toggles which classes compile, so rm ALL *.o first (and regen wlan_firmware.o from $TEMP/wlan_firmware.S since rm deletes it, no make rule). scripts/build-local.ps1:256/316 + CI ALWAYS pass these defines -- a manual `make` that omits them silently builds the broken CS42448 kernel. DECISIVE LIVE WITNESS = a new :4445 DIAG verb (commit aaced2e on branch fix/usb-audio-no-output): walkN=3 typeMask=9004 outGate climbing but outUpd=0 => the 0x8000 OUTPUT node walked+update()-called is NOT AudioOutputUSB (it's AudioOutputTDM) => wrong build. After USB build: outWr/outUpd climbing, outConn=2, outPeak>0 (was 0), outUR stops flooding, USER CONFIRMED audible output. Also fixed (robust, kept): AudioInputUSB::claimUpdateResponsibility() at IN late-bind (input_usb) so the graph-tick gate opens regardless of boot handshake (inResp was 0); doUpdate sink-gate `|| getType()==AUDIO_DEVICE_OUTPUT`. Deploy: tftproot/7bec0617/kernel7l.img + REBOOT :4444 (or power-cycle if soft reboot wedges netboot).
