## Looper PAUSE = MUTE, play head never stops (commit a99f68a)

Pausing a recorded loop (per-track STOP_TRACK -> LOOP_COMMAND_STOP on CS_PLAYING/CS_LOOPING) no longer resets the head or drops to CS_RECORDED. It latches a clip-level m_paused (Looper.h publicClip) that gates ONLY the output via a click-free per-block m_pauseGain ramp (1/16 per block toward 0 paused/1 playing, per-sample interpolated, loopClipUpdate.cpp). The clip STAYS CS_PLAYING/CS_LOOPING so the play-head advance (which runs OUTSIDE the !m_mute output guard) keeps advancing every block, phase-locked to masterPhase. Resume (LOOP_COMMAND_PLAY on a paused clip) just clears m_paused - NO _startPlaying re-anchor - so position never changes and rapid mute/unmute is instant. Once recorded a loop never stops playing the same way it started: head continuous on masterPhase forever, pause only mutes. loopTrack.cpp getTrackState reports a CS_PLAYING/CS_LOOPING clip with isPaused() as TRACK_STATE_STOPPED (not PLAYING) so the pad blinks yellow (MFS_LOOPER_PAUSED) and the paused-tap gesture resumes it; per-clip VU reads the gated output. Pause does NOT touch incDecRunning (stays in running set, advancing). stopImmediate (shift+STOP/abort) and _startRecording clear m_paused/m_pauseGain (real stop, head reset, audible). Distinct from m_mute (volume mute).
