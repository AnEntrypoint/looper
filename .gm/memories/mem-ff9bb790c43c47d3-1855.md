## UCA222 extra latency (past-week) = the UAC2 OUT double-buffer applied to ALL devices; now UAC2-gated (commit 87710dc, 2026-06-23)

SYMPTOM: looper monitoring/round-trip latency grew ~1ms+ after the Tascam US-2x2 (UAC2) compatibility work. ROOT CAUSE: usbaudiodevice.cpp CUSBAudioDevice::Configure submitted BOTH OUT URBs up front (StartOutRequest(0); StartOutRequest(1)) UNCONDITIONALLY -> the iso OUT pipe is double-buffered (2 URBs always in flight) for EVERY device incl UCA222. That covers the high-speed async-OUT re-arm gap the Tascam needs (it misses microframes during per-URB re-arm), but costs ~1 URB period of OUT latency. Pre-Tascam (ab3dd58^) submitted ONE OUT URB; the full-speed UCA222 (UAC1, 1ms re-arm window) never had the gap problem so it never needed the second URB. The OTHER UAC2 additions (avail=256 ring PI rate-trim s_outBias, N=8 multi-iso batching) were ALREADY UAC2-gated (inside if(m_bUAC2 && m_pEndpointFb)) so they never touched UCA222. FIX: gate the second URB on UAC2 -- always StartOutRequest(0); StartOutRequest(1) only if (m_bUAC2 && m_pEndpointFb). m_bUAC2 set in ConfigureUAC2() before the OUT submission so the gate is valid; OutCompletion re-arms per-slot so a single slot-0 self-sustains; ~dtor delete of null slot-1 URB is safe. UCA222 back to single-URB low latency; Tascam keeps double-buffer. Secondary minor add NOT changed: output_usb.cpp:165 reader seeds wr_snap-128 (~2.7ms) vs pre-Tascam ~96 (nSamples*2) = ~0.67ms -- left as-is because UCA222 has no UAC2 PI rate trim, so the seed is its only underrun cushion and lowering risks clicks. PRINCIPLE (user): compatibility latency added for one device must be conditional on that device, not global. Verify: :4445 UAUD outDeliv cadence ~1000/s single-URB + lower outAvail + no new outUR on UCA222. See [[looper-audio-architecture]], the uac2 host memory.
