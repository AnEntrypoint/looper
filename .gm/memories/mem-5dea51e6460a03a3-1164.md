## Bare-metal Pi station leases from the esp32 'ticker' AP only with the BOOTP broadcast flag (commit ade471f)

The Pi (bcm4343, no IP stack/ARP on WLAN) joins the open 'ticker' AP (an ESP32 softAP serving Ableton Link) as a STATION and DHCP-leases from it. A bare-metal station has no configured IP/ARP, so a UNICAST DHCP OFFER to the offered IP/MAC is never received -> no lease (was: dhcpAtt=15, fell back to hosting own AP). FIX: set the BOOTP broadcast flag (flags field at dhcp+10 = 0x8000) in BOTH DISCOVER and REQUEST (wlanDHCP.cpp buildDiscover/buildRequest) so the server BROADCASTS OFFER/ACK and the single-RX demux (wlanDhcpClientFrame, dst :68, not IP-filtered) sees it. With this + the 2s DISCOVER retry, the Pi leases on the FIRST attempt. LIVE witness :4445 WLAN: wlan=joined-ticker dhcpOK=1 dhcpAtt=1 rxFrames=695 dhcpRx=2 dhcpOffers=1 ownip=192.168.4.2; LINK peers=2 peerip=192.168.4.1. Diagnosed via new rxFrames/dhcpRx/dhcpOffers counters in the WLAN verb. kernel.cpp now JoinOpenNet-first (3x retry) with runtime wlanFallbackToAP() only if a joined ticker yields no lease. Remaining after lease: Link measurement one-way (pongsRx=0, synced=0).
