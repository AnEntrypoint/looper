## Looper clip FSM rationalization — first-loop exact-region (commit follows 3a24513)

The first loop 'didn't repeat the exact recorded region / played from a funny place'. Root cause was a tangled record->play handoff with THREE overlapping mechanisms. Fixes (all in loopClip.cpp/loopClipUpdate.cpp):
(1) TAIL-NO-SELF-CROSSFADE: in CS_RECORDING_TAIL the pp_main advance previously ran the self-advance branch and called _startCrossFade() at play==num_blocks, flipping to CS_LOOPING MID-TAIL so _finishRecording (gated TAIL/FINISHING at record_block>=max_blocks) never fired and incDecRunning double-counted. FIX: explicit CS_RECORDING_TAIL advance branch wraps the monitor head with NO state change; wrap/crossfade transitions are now ALWAYS gated on m_state==CS_PLAYING. TAIL ends only via _finishRecording.
(2) _startCrossFade WRAP-TO-0: it set crossfade_start=play_block(==num_blocks, the outgoing tail) but left play_block at num_blocks, so CS_LOOPING read getBlock(num_blocks) (tail) as the main head instead of block 0. FIX: m_play_block=0 (new loop restarts exact region) + crossfade_start=num_blocks (tail crossfades out).
(3) SEAMLESS HANDOFF: _finishRecording now calls _startPlaying(preservePlayBlock=true) so the TAIL monitor head continues (no backward jump of CROSSFADE blocks); fresh resume uses preservePlayBlock=false to re-anchor.
Also: _backdatedRecordLength (M==0 first loop) floored at CROSSFADE_BLOCKS*2 (matches M>0 quantize floor). New :4445 CLIP[<n>] verb (loopClipTelemetry) shows track/state/play/rec/num/max/running. Host test scripts/test-first-loop-region.cpp ALL PASS (FAILED on pre-fix seam 20->0, passes after). Playback-advance is now ONE rule keyed on state then (has-master,L vs M): TAIL=monitor-wrap-no-state; sub-phrase=phase-formula; first/long/no-master=self-advance+_startCrossFade. All gated CS_PLAYING.
